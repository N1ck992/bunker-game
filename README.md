# Bunker Prototype — первый вертикальный срез

## Как запустить

Открывать `index.html` двойным кликом **не сработает** — игра грузит JSON и
картинку через `fetch`, а браузеры блокируют это для `file://`. Нужен любой
локальный http-сервер из папки `bunker-prototype-1/`:

```bash
cd bunker-prototype-1
python3 -m http.server 8000
```

Затем открыть `http://localhost:8000` в браузере компьютера или телефона
(в одной Wi-Fi сети — `http://<IP-компьютера>:8000`).

## Что уже работает (соответствует Этапам 1–4 из ТЗ)

- Загрузка изображения бункера + отдельная логическая карта проходимости
  (`game/map/bunker-map.json`), полностью отделённая от картинки.
- Тап по экрану → персонаж строит путь (A*) и идёт сам, не проходя сквозь стены —
  управление только тапом, без кнопок (как в Fallout Shelter): тап по полу — идти
  туда, тап по двери — открыть окно с информацией, тап по персонажу — выбрать его.
- Житель отрисован вашим артом вместо кружка: поза «стоит» в покое, 3-кадровый
  цикл «бежит» во время движения (переключение кадров по таймеру, ~7 кадров/сек),
  поза «осматривает» на пару секунд при тапе по двери. Спрайт разворачивается
  влево/вправо по направлению движения. Стопы теперь всегда упираются в пол —
  раньше персонаж «висел в воздухе» из-за того, что маска прозрачности
  затухала у самого низа спрайта; сейчас низ спрайта всегда непрозрачен, тает
  только верх/края.
- Первая комната (`room_01`) уже открыта и производит немного воды и тепла.
- Вторая комната за дверью «A» заблокирована — открывается за стройматериалы
  (тап по красной рамке двери → окно с ценой).
- Дверь «01» (выход на поверхность) и лестница вниз размечены на карте, но
  заблокированы по сюжету — это задел на следующие этапы, не баг.
- Ресурсы (вода/еда/тепло/материалы) считаются как производство−потребление
  каждые несколько секунд; еда сейчас только тратится — это осознанно:
  открытие кухни за дверью «A» становится первой стратегической целью.
- Смена дня/ночи (15/15 минут по умолчанию, см. `balance.json`), лёгкое
  затемнение сцены ночью.
- Голод/жажда/здоровье персонажей тикают, при критических значениях житель
  становится Inactive (не умирает — как и требовалось).
- Сохранение в localStorage (автосейв раз в 20 сек).

## Про арт персонажа

Вы прислали лист с тремя состояниями — «СТОИТ», «ОСМАТРИВАЕТ», «БЕЖИТ» (по 3
ракурса/кадра каждое). Из «СТОИТ» и «ОСМАТРИВАЕТ» взял по одной фронтальной позе,
из «БЕЖИТ» — все 3 кадра как цикл бега (`char_run_0/1/2.png`). Все спрайты обрезаны
так, чтобы стопы были ровно на нижней границе картинки — раньше персонаж «плавал»
над полом из-за того, что маска прозрачности затухала у самого низа. Тёмная одежда
близка по тону к фону листа, поэтому точный вырез по силуэту давал шум — использую
мягкую маску, где затухают только верх и края, а низ всегда сплошной.

Сейчас это простое переключение готовых кадров по таймеру (idle / бег по 3 кадрам /
осматривает), не настоящий скелет и не интерполяция между позами — для прототипа
достаточно. Если пришлёте более длинный цикл бега или анимацию поворота, добавить
будет просто: меняется только `_loadCharacterSprites`/`_renderCharacters` в
`Game.js`, остальная логика не трогается.

## Про изображение бункера

Вы прислали один комбинированный арт (поверхность + подземный бункер). Я
использовал нижнюю подземную часть как изображение первой комнаты/уровня −1
(`game/assets/bunker/bunker-interior.png`), а полный арт сохранил как
`bunker-full.png` — пригодится позже для сцены выхода на поверхность / карты
мира. Логическая карта (`bunker-map.json`) — грубая ручная разметка под этот
конкретный арт (проходимая зона, дверь «01» слева, дверь «A» справа, лестница
по центру). Когда пришлёте следующие изображения (вторая комната, новые этажи
и т.д.), их нужно будет так же разметить отдельным JSON — код уже на это
рассчитан (см. раздел 33 ТЗ и §24 «визуальный слой + логический слой»).
