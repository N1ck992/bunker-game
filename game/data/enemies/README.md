# Враги — структура данных

Каждая **раса** — отдельный JSON-файл в этой папке (`<race_id>.json`), плюс
запись о нём в `index.json`, чтобы игра знала, что грузить.

## Добавить новую расу

1. Создать `game/data/enemies/<race_id>.json` по образцу `wasteland_raiders.json`.
2. Добавить `"<race_id>"` в массив `races` в `index.json`.
3. Создать папку под арт: `game/assets/enemies/<race_id>/`.

## Добавить нового юнита в существующую расу

Просто добавить объект в массив `"units"` файла расы. Рекомендуемый лимит —
около 5 юнитов на расу (не жёсткое ограничение, просто ориентир из ТЗ).
Схема юнита:

```json
{
  "id": "unit_id",                 // уникален в пределах расы
  "name": "Отображаемое имя",
  "health": 40,
  "damage": 6,                     // урон за одну атаку
  "attackRange": 1.5,              // дистанция атаки в клетках
  "aggroRange": 6,                 // дистанция, с которой замечает героя
  "attackCooldownSeconds": 1.6,    // пауза между атаками
  "tilesPerSecond": 2.2,           // скорость бега при погоне
  "sprites": {
    "idle": "game/assets/enemies/<race_id>/<unit_id>/idle.png",
    "run": ["run_0.png", "run_1.png", "run_2.png"],   // 3-кадровый цикл, как у персонажа
    "attack": ["attack_0.png", "attack_1.png", "attack_2.png"]
  }
}
```

Спрайты грузятся один раз на тип юнита и переиспользуются между всеми его
копиями на карте (см. `Game._loadEnemySprites`) — можно спокойно ставить
десяток одинаковых рейдеров, картинки не задублируются в памяти.

## Где враги реально появляются на карте

Список **экземпляров** (кто, где) — не здесь, а в `game/map/<уровень>.json`
(сейчас `bunker-map.json`) в массиве `"enemies"`, по аналогии с
`"interactables"`. Один и тот же тип юнита можно ставить на карту сколько
угодно раз с разными `id`/координатами.

## Логика поведения

Общая для всех рас и юнитов, живёт в `game/systems/EnemySystem.js` и
`game/entities/Enemy.js` — данные (`health`, `aggroRange` и т.д.) просто
подставляются в неё, отдельный код на расу/юнита писать не нужно.
